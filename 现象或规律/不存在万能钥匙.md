# 不存在万能钥匙

## 不存在能解决一切问题的方法

不要试图为每个问题找到对应的"方法"。

根本原因有二。

### 一、关键点很难抓对

任何问题摆在面前，你首先需要确定：**哪些点是相关的？哪些点是关键？**

但这个问题本身就是问题——如果你已经知道哪些点是关键，那问题已经解决一半了。恰恰是**因为你不知道**，你才需要方法。

而"该注意什么"这件事，方法本身回答不了。大部分问题真正的困难就在于：**你很可能抓错了关键点**，而且你甚至不知道自己抓错了。方法只能在你**已经选定了关注范围之后**，帮你更高效地处理这个范围内的东西。但如果关注范围本身就是偏的，方法只会让你在错误的方向上走得更快。

> 方法解决了"怎么走"，但解决不了"往哪看"——而"往哪看"才是大多数问题真正难的地方。

### 二、方法本质上是启发式的

所谓方法，本质上是一组**基于经验的启发式规则（heuristic）**：

- 在大部分情况下有用
- 但不是永远有用
- 换一个上下文可能完全失效

如果存在一种方法能稳定解决某一类问题，那它就不叫方法了——它叫**算法**。算法可以自动化，可以交给机器执行。方法不能，因为方法依赖人的判断。

| | 算法 | 方法（启发式） |
|--|------|--------------|
| 输入 | 明确的 | 模糊的 |
| 输出 | 确定的 | 近似的 |
| 适用边界 | 清晰 | 模糊 |
| 可靠性 | 高 | 中等 |

### 所以

方法是有用的——它可以给你一个**起点**、一个**思考框架**、一组**可试的方向**。

但不要迷信方法。不要觉得"问题解决不了是因为我还没找到对的方法"。更多时候，问题解决不了是因为：

- 还没看清问题的结构
- **关键点本身就很难抓对**
- 对这个上下文的理解还不够深

方法能帮你整理已知的东西，但无法替你发现你没看到的东西。
