# 跳跃性交互式查询

## 核心思想

**面对一个"看起来新"的问题，先用已有方法/工具去套，而不是从头造新方案。**

但这个"套"不是硬套，而是一个跳跃性很大的交互式查询过程：

- 你不确定答案在哪
- 你只有一些模糊的线索
- 外部环境可以是**工具**、**人**、**资料**、**网络**
- 查一步、看结果、再决定下一步

## 跳跃性交互式查询的两个根基

这个方法的两个关键能力——"跳跃"和"交互"——分别来自两个地方：

### 跳跃性 ← 深度（来自反思与复盘与推演）

为什么能从"底贴"跳到"水印"？因为你在脑中做了深度的抽象化，穿透了表象，看到了深层结构的相似。

跳跃的距离取决于抽象的深度：

- **浅抽象** → 只能跳到同类场景（底贴 → 另一个底贴）
- **够深的抽象** → 能跳到完全不同领域的场景（底贴 → 卡尔曼滤波忘了怎么算 → 去翻书）

深度来自 [[反思与复盘与推演]]——不是靠"学一个跳跃技巧"，而是靠反复抽象化，让大脑自动学会在差异大的问题之间感觉到"像"。

### 交互性 ← 知道"位置"

为什么能去翻格式工厂？因为你知道**工具可能存在**。为什么能去翻书？因为你知道**那本书上有**。

交互性的前提是：**你对"哪里可能有答案"有一个大致的方向**。

这个"位置感"来自：
- 对工具生态的了解（"好像有个叫格式工厂的软件"）
- 对知识分布的了解（"那本书上有"、"老张做过"）
- 对信息源的了解（"Stack Overflow 上应该有人问过"）

没有位置感，交互就变成了瞎翻。

### 两者缺一不可

| 缺 | 结果 | 表现 |
|----|------|------|
| 深度够 + 不知道去哪找 | 能感觉到"像"，但不知道下一步该干嘛 | 有直觉但行动力不足 |
| 深度不够 + 知道位置 | 知道去哪找，但认不出匹配信号 | 翻了很多但错过了答案 |
| 深度够 + 知道位置 | 能跳得远、也能找到 | 就是底贴那次的结果 |

## 操作方式

### 1. 触发：判断"能不能偷懒"

当遇到问题时，先不急着分析问题本身，而是问：

> 这个问题有没有可能用我已知的东西解决？

这个判断往往是**情绪驱动**的——"写程序太麻烦了"、"肯定有现成的工具"。不要忽视这种情绪，它本身就是查询的起点。

### 2. 检索：生成模糊线索

在脑内搜索可能的候选方向：

- "好像有个叫 XX 的软件……"
- "我记得有人做过类似的事……"
- "这个和 XX 可能有点像……"

**容忍不确定性**——线索不需要百分之百确定，"好像有"就值得去找一下。

### 3. 扩展：把外部环境变成候选集

不要只依赖脑内检索。这个"外部环境"可以是多种形式：

- **工具**：打开一个软件、翻它的功能列表
- **人**：你不知道答案，但你知道**谁可能知道**——"老张做过类似的项目"、"这个团队应该处理过"
- **资料**：忘了卡尔曼滤波怎么算，但你知道**哪本书上有**，或者**网上搜一下关键词能找到**

关键是把外部信息空间当作候选集来扫描，而不是在脑内空想。

关键动作是：**打开 → 翻看 → 等匹配信号出现**。

### 4. 捕捉：响应低强度的匹配信号

在扫描过程中，如果某个候选让你"停了一下"——那就是注意力的捕捉事件。不要忽略它，停下来认真比对。

匹配信号往往是**模糊的、低强度的**——"底贴和水印好像有点像？"它不会大声告诉你"就是这个"，需要你主动停下来确认。

### 5. 比对：验证深层结构特征

停下后不是直接接受，而是比对多个特征维度：

- 新问题需要什么？
- 候选方案做了什么？
- 它们在**深层结构**而不是表象上是否一致？

## 适用场景

- 遇到一个"没见过"的问题，但感觉可能和别人家的某类问题类似
- 不确定有没有现成方案，但值得去找一下
- 手头没有明确的解法，但有模糊的线索可以追
- 忘了某个知识点，但知道哪本书/哪个人/网上哪里能找到

## 实际上很常用

你可能每天都在用这个方法，只是没有意识到它叫"跳跃性交互式查询"：

| 场景 | 线索 | 外部候选集 | 匹配信号 |
|------|------|-----------|---------|
| 忘了卡尔曼滤波怎么算 | 好像那本书上有 | 书架上的书脊 | 看到那本书 |
| 不知道代码为什么报错 | 好像 Stack Overflow 有人问过 | 搜索结果的标题列表 | 某个标题描述很像 |
| 需要一个 UI 组件 | 好像 Ant Design 有类似的 | 翻组件文档 | 看到某个组件描述匹配 |
| 不知道谁负责这个模块 | 好像听小王提过 | 翻通讯录 / 问一圈 | 有人指路 |

## 与 [[概念/认知功能/查询]] 的关系

这个方法本质上就是把 [[概念/认知功能/查询]] 这个先天能力**有意识地外化**——不是等脑子里自动蹦出答案，而是主动制造触发条件，把外部环境变成检索空间，让注意力去捕捉匹配信号。

## 常见断裂点

跳跃性交互式查询的每一步都可能断掉：

- 情绪信号不够强 → 直接硬做，不会去找现成方案
- 不知道去哪找 → 实际上可以问人、搜资料、翻书
- 只依赖脑内检索 → 查不到就放弃
- 扫得太快 → 匹配信号还没出现就跳过了
- 看到候选但不停下来 → 错过匹配
- 只比表象不比深层特征 → "这是 A 不是 B"，拒绝迁移

每一步断裂，查询就失败。
