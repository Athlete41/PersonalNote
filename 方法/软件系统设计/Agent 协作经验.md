# Agent 协作经验

1. 把 Agent 当外部系统，用 [[方法/交互式学习法]] 摸清它的行为规律和边界来协作。摸清了再用，而不是上来就干。

2. 大部分 Agent 可以用来认知协作——你的大部分思考工作都可以与它讨论协商，防止陷入局部最优解。设计上的决策它不是最终拍板的，但作为讨论对象能帮你想得更全。

3. 生成式任务本质上是需求落地到具体实现，从一个较抽象的描述逐步具象化。这个过程必然伴随随机性——同一段 prompt 每次产出的结果不完全一样。如果你不信任 Agent 在某个地方的落地能力，在不信任的地方给例子，相当于提前做了一个具体化，缩小它的随机空间。

4. 可以尝试不同 Agent——这是第 2 条的变体。不同 Agent 的知识分布、推理习惯不一样，换一个 Agent 来审视同一个问题，相当于换个角度，也有防止局部最优解的功效。

5. Agent 的**主动性太弱**。人看到你漏了什么东西会主动问你，但 Agent 很少主动开口——它不知道自己不知道，甚至可能幻觉出一个自信的答案。即便现在有些 Agent 有了怀疑机制，主动性依然受限于它的机制设计。所以协作中你需要承担更多的**主动提问和检查**，不能指望它自己发现问题。

总的来说，把 Agent 当成协作的人来对待——陌生时期试探、熟悉后有信任区、关键点和坑像教同事一样教给它、不懂的可以问它、它也能反过来教你关键点和坑。记住第 5 条：它不会主动开口，你得主动去问去查。
