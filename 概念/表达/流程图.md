# 流程图

## 它表达什么

流程图关注系统的**决策分支**、**处理步骤**、**异常路径**，提取它们的**控制流**——即什么条件下走哪条路。

| 关注点 | 提取什么 |
|--------|---------|
| **决策分支** | 条件判断——if-then-else，什么情况下走 A、什么情况下走 B |
| **处理步骤** | 每一步做什么操作，步骤之间的先后关系 |
| **异常路径** | 出错、超时、校验不通过时怎么走 |

流程图是唯一明确表达**决策节点**的图。菱形框代表"这里要判断"，不同出口代表不同分支。它回答的是"一个请求/任务从开始到结束，中间经历了哪些判断和操作"。

## 它不表达什么

- **不表达结构** — 组件之间怎么连接、边界在哪，不画在流程图上，那是架构图的事
- **不表达时序** — 消息谁先发谁后发、交互顺序，不画在流程图上，那是时序图的事
- **不表达状态变迁** — 一个对象有多少种状态、状态之间怎么转换，不画在流程图上，那是状态图的事
- **不表达粒度** — 一个步骤可能是一行代码、一个函数、一个服务，流程图不区分执行粒度

一张流程图里如果出现了多个系统的连接框、消息的发送顺序编号——说明它混入了不该画的东西。
